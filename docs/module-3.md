## 1. Templates with Jinja2

### The template module

The `template` module renders a Jinja2 file and copies the result to the target.

```yaml title="playbooks/04_templates.yml (excerpt)"
- name: Deploy a config file
  hosts: servers
  gather_facts: false

  tasks:
    - name: Render the config template
      ansible.builtin.template:
        src: myconfig.conf.j2
        dest: /tmp/myconfig.conf
        mode: "0644"
```

### Jinja2 basics

Create a template file `playbooks/templates/myconfig.conf.j2`:

```jinja title="playbooks/templates/myconfig.conf.j2"
# Configuration for {{ inventory_hostname }}
# Generated by Ansible

hostname {{ ansible_hostname }}
domain_name {{ ansible_domain | default('example.com') }}
timezone {{ ansible_date_time.timezone | default('UTC') }}

# Network settings
{% for iface in ansible_interfaces %}
interface {{ iface }}
{% endfor %}

# This host has {{ ansible_processor_vcpus | default('unknown') }} CPU(s)
```

### Jinja2 filters

Filters transform variable values. Common ones:

| Filter | Example | Result |
|--------|---------|--------|
| `default` | `{{ var \| default('fallback') }}` | Uses 'fallback' if var is undefined |
| `upper` | `{{ hostname \| upper }}` | UPPERCASE |
| `lower` | `{{ hostname \| lower }}` | lowercase |
| `to_json` | `{{ data \| to_json }}` | JSON string |
| `to_yaml` | `{{ data \| to_yaml }}` | YAML string |
| `bool` | `{{ "yes" \| bool }}` | true |
| `ternary` | `{{ enabled \| ternary('on', 'off') }}` | 'on' or 'off' |

### Exercise: Template a simple web page

1. Create `playbooks/templates/index.html.j2`:

```jinja title="playbooks/templates/index.html.j2"
<!DOCTYPE html>
<html>
<head>
    <title>{{ page_title | default('Ansible Workshop') }}</title>
</head>
<body>
    <h1>Welcome to {{ ansible_hostname }}</h1>
    <p>Managed by Ansible</p>
    <p>OS: {{ ansible_distribution }} {{ ansible_distribution_version }}</p>
    <p>Uptime: {{ ansible_uptime_seconds | default('unknown') }} seconds</p>
    <hr>
    {% for service in services %}
    <p>Service: {{ service.name }} - {{ service.status }}</p>
    {% endfor %}
</body>
</html>
```

2. Create a playbook `playbooks/04_templates.yml`:

```yaml title="playbooks/04_templates.yml"
- name: Deploy a dynamic web page
  hosts: servers
  gather_facts: true

  vars:
    page_title: "My Workshop Page"
    services:
      - { name: ssh, status: running }
      - { name: nginx, status: stopped }

  tasks:
    - name: Create the web directory
      ansible.builtin.file:
        path: /var/www/html
        state: directory
        mode: "0755"

    - name: Deploy the index page
      ansible.builtin.template:
        src: index.html.j2
        dest: /var/www/html/index.html
        mode: "0644"

    - name: Show the rendered file
      ansible.builtin.command: cat /var/www/html/index.html
      register: page_content

    - name: Display the page
      ansible.builtin.debug:
        var: page_content.stdout_lines
```

3. Run it:

```bash
ansible-playbook playbooks/04_templates.yml
```

## 2. Roles

### What is a role?

A role is a structured way to organize playbooks, variables, templates, and handlers. It promotes reusability.

### Role directory structure

```
roles/my_role/
├── tasks/
│   └── main.yml        # Main task list
├── vars/
│   └── main.yml        # Variables
├── templates/          # Template files
├── handlers/
│   └── main.yml        # Handlers
├── defaults/
│   └── main.yml        # Default variables (lowest precedence)
└── files/              # Static files to copy
```

### Creating a role

Use the `ansible-galaxy` command:

```bash
ansible-galaxy init roles/web_server
```

This creates the directory structure above.

### Using a role in a playbook

```yaml title="playbooks/05_roles.yml"
- name: Configure web servers using a role
  hosts: servers
  gather_facts: true

  roles:
    - web_server
```

### Exercise: Refactor a playbook into a role

1. Start with this flat playbook:

```yaml title="playbooks/05_roles_flat.yml (starting point)"
- name: Configure web server (flat)
  hosts: servers
  gather_facts: false

  vars:
    web_port: 80
    document_root: /var/www/html

  tasks:
    - name: Create document root
      ansible.builtin.file:
        path: "{{ document_root }}"
        state: directory
        mode: "0755"

    - name: Deploy index page
      ansible.builtin.template:
        src: index.html.j2
        dest: "{{ document_root }}/index.html"
        mode: "0644"

    - name: Ensure nginx is installed
      ansible.builtin.package:
        name: nginx
        state: present

    - name: Ensure nginx is running
      ansible.builtin.service:
        name: nginx
        state: started
        enabled: true
```

2. Refactor into a role at `roles/web_server/`:

   - `roles/web_server/tasks/main.yml` — move tasks here
   - `roles/web_server/defaults/main.yml` — move variables here as defaults
   - `roles/web_server/templates/index.html.j2` — move template here

3. Create the role:

```bash
ansible-galaxy init roles/web_server
```

4. Move the files:

```bash
# Create task file
cat > roles/web_server/tasks/main.yml << 'EOF'
- name: Create document root
  ansible.builtin.file:
    path: "{{ document_root }}"
    state: directory
    mode: "0755"

- name: Deploy index page
  ansible.builtin.template:
    src: index.html.j2
    dest: "{{ document_root }}/index.html"
    mode: "0644"

- name: Ensure nginx is installed
  ansible.builtin.package:
    name: nginx
    state: present

- name: Ensure nginx is running
  ansible.builtin.service:
    name: nginx
    state: started
    enabled: true
EOF

# Create defaults
cat > roles/web_server/defaults/main.yml << 'EOF'
document_root: /var/www/html
web_port: 80
EOF

# Move template (already exists from Module 3)
cp playbooks/templates/index.html.j2 roles/web_server/templates/
```

5. Create the role-based playbook `playbooks/05_roles.yml`:

```yaml title="playbooks/05_roles.yml"
- name: Configure web servers using a role
  hosts: servers
  gather_facts: true

  roles:
    - web_server
```

6. Run it:

```bash
ansible-playbook playbooks/05_roles.yml --check
```

### When to use a role

Use a role when:
- You want to reuse the same configuration across multiple playbooks
- The configuration has multiple tasks, variables, and templates
- You want to share it with others (via Ansible Galaxy)

Keep it simple: a flat playbook is fine for one-off tasks.
